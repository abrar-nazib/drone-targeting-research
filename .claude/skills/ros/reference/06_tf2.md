# tf2: Coordinate Frames (ROS 2 Jazzy)

> Sources: tf2 concept page + Intermediate tf2 tutorial series

tf2 is the ROS 2 transform library that tracks multiple coordinate frames over
time. For a drone perception stack it is the spine that connects the IMU,
cameras, lidar, body frame, simulator-world frame, and target detections so
that any measurement expressed in one frame can be mapped to any other frame
at any past or current timestamp.

Quick mental model:

- A **frame** is a 3D coordinate system with a string name (e.g. `base_link`,
  `camera_optical`, `world`).
- A **transform** is the 6-DoF pose (translation + rotation quaternion) of a
  child frame expressed in its parent frame.
- Frames are organized as a **tree** (one parent per child).
- **Broadcasters** publish `geometry_msgs/TransformStamped` onto `/tf` (dynamic,
  high rate) or `/tf_static` (latched, one-shot).
- A **TransformListener** subscribes to those topics and fills a **Buffer**.
- Any node can ask the buffer `lookup_transform(target, source, time)` to
  get the chained transform.

CLI cheat sheet covered in this file:

| Command | Purpose |
|---|---|
| `ros2 run tf2_ros static_transform_publisher --x ... --frame-id A --child-frame-id B` | Publish a constant transform A->B |
| `ros2 run tf2_ros tf2_echo <target> <source>` | Print live transform between two frames |
| `ros2 run tf2_ros tf2_monitor <target> <source>` | Print delay / rate stats for a transform chain |
| `ros2 run tf2_tools view_frames` | Generate `frames.pdf` of the whole tree |

## About tf2 (concept)
**Source**: https://docs.ros.org/en/jazzy/Concepts/Intermediate/About-Tf2.html

tf2 is "the transform library, which lets the user keep track of multiple
coordinate frames over time". It maintains the relationships between frames
in a tree and lets any subscriber answer temporal+spatial queries such as
"where was the head frame relative to the world frame 5 seconds ago" or
"what is the pose of the object in my gripper relative to my base".

Key properties:

- **Distributed**: tf2 information is published over standard ROS 2 topics
  (`/tf`, `/tf_static`), so any node on any machine in the graph has access.
  Designs commonly use one centralized publisher per source, but each node
  may also publish its own frames.
- **Tree structure**: every frame has exactly one parent. Compound transforms
  between arbitrary frames are computed by walking the tree (up to the
  common ancestor, then down) and composing.
- **Static vs dynamic**: static transforms are sent once on `/tf_static`
  (a latched topic), reducing bandwidth and storage. Dynamic transforms
  are republished on `/tf` at high rate and stored in a time-indexed buffer.
- **Broadcasters / listeners**: a node publishes transforms with a
  `TransformBroadcaster` or `StaticTransformBroadcaster`. A node consumes
  them by creating a `Buffer` and a `TransformListener`.

The wire type for both topics is `tf2_msgs/TFMessage`, which is a vector of
`geometry_msgs/TransformStamped`. A `TransformStamped` carries:

- `header.stamp` — the time the transform is valid for
- `header.frame_id` — parent frame
- `child_frame_id` — child frame
- `transform.translation` (`x,y,z`)
- `transform.rotation` (quaternion `x,y,z,w`, **w-last**)

Per the concept page: "Transforms published in the `geometry_msgs/msg/Transform`
message represent the frame formulation" — i.e. the message describes how the
child frame is positioned and oriented inside the parent frame.

## Writing a static broadcaster (Python)
**Source**: https://docs.ros.org/en/jazzy/Tutorials/Intermediate/Tf2/Writing-A-Tf2-Static-Broadcaster-Py.html

A static broadcaster publishes a transform that never changes (sensor mounting,
URDF-like fixed offsets, world->map). Internally `StaticTransformBroadcaster`
uses a latched topic so a single `sendTransform` call is enough — late
subscribers still receive it.

**Full Python node `static_turtle_tf2_broadcaster.py`:**

```python
import math
import sys

from geometry_msgs.msg import TransformStamped

import numpy as np

import rclpy
from rclpy.node import Node

from tf2_ros.static_transform_broadcaster import StaticTransformBroadcaster

def quaternion_from_euler(ai, aj, ak):
    ai /= 2.0
    aj /= 2.0
    ak /= 2.0
    ci = math.cos(ai)
    si = math.sin(ai)
    cj = math.cos(aj)
    sj = math.sin(aj)
    ck = math.cos(ak)
    sk = math.sin(ak)
    cc = ci*ck
    cs = ci*sk
    sc = si*ck
    ss = si*sk

    q = np.empty((4, ))
    q[0] = cj*sc - sj*cs
    q[1] = cj*ss + sj*cc
    q[2] = cj*cs - sj*sc
    q[3] = cj*cc + sj*ss

    return q

class StaticFramePublisher(Node):
    """
    Broadcast transforms that never change.

    This example publishes transforms from `world` to a static turtle frame.
    The transforms are only published once at startup, and are constant for all
    time.
    """

    def __init__(self, transformation):
        super().__init__('static_turtle_tf2_broadcaster')

        self.tf_static_broadcaster = StaticTransformBroadcaster(self)

        # Publish static transforms once at startup
        self.make_transforms(transformation)

    def make_transforms(self, transformation):
        t = TransformStamped()

        t.header.stamp = self.get_clock().now().to_msg()
        t.header.frame_id = 'world'
        t.child_frame_id = transformation[1]

        t.transform.translation.x = float(transformation[2])
        t.transform.translation.y = float(transformation[3])
        t.transform.translation.z = float(transformation[4])
        quat = quaternion_from_euler(
            float(transformation[5]), float(transformation[6]), float(transformation[7]))
        t.transform.rotation.x = quat[0]
        t.transform.rotation.y = quat[1]
        t.transform.rotation.z = quat[2]
        t.transform.rotation.w = quat[3]

        self.tf_static_broadcaster.sendTransform(t)

def main():
    logger = rclpy.logging.get_logger('logger')

    # obtain parameters from command line arguments
    if len(sys.argv) != 8:
        logger.info('Invalid number of parameters. Usage: \n'
                    '$ ros2 run learning_tf2_py static_turtle_tf2_broadcaster'
                    'child_frame_name x y z roll pitch yaw')
        sys.exit(1)

    if sys.argv[1] == 'world':
        logger.info('Your static turtle name cannot be "world"')
        sys.exit(2)

    # pass parameters and initialize node
    rclpy.init()
    node = StaticFramePublisher(sys.argv)
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass

    rclpy.shutdown()
```

## Writing a static broadcaster (C++)
**Source**: https://docs.ros.org/en/jazzy/Tutorials/Intermediate/Tf2/Writing-A-Tf2-Static-Broadcaster-Cpp.html

**Full `static_turtle_tf2_broadcaster.cpp`:**

```cpp
#include <memory>

#include "geometry_msgs/msg/transform_stamped.hpp"
#include "rclcpp/rclcpp.hpp"
#include "tf2/LinearMath/Quaternion.hpp"
#include "tf2_ros/static_transform_broadcaster.hpp"

class StaticFramePublisher : public rclcpp::Node
{
public:
  explicit StaticFramePublisher(char * transformation[])
  : Node("static_turtle_tf2_broadcaster")
  {
    tf_static_broadcaster_ = std::make_shared<tf2_ros::StaticTransformBroadcaster>(this);

    // Publish static transforms once at startup
    this->make_transforms(transformation);
  }

private:
  void make_transforms(char * transformation[])
  {
    geometry_msgs::msg::TransformStamped t;

    t.header.stamp = this->get_clock()->now();
    t.header.frame_id = "world";
    t.child_frame_id = transformation[1];

    t.transform.translation.x = atof(transformation[2]);
    t.transform.translation.y = atof(transformation[3]);
    t.transform.translation.z = atof(transformation[4]);
    tf2::Quaternion q;
    q.setRPY(
      atof(transformation[5]),
      atof(transformation[6]),
      atof(transformation[7]));
    t.transform.rotation.x = q.x();
    t.transform.rotation.y = q.y();
    t.transform.rotation.z = q.z();
    t.transform.rotation.w = q.w();

    tf_static_broadcaster_->sendTransform(t);
  }

  std::shared_ptr<tf2_ros::StaticTransformBroadcaster> tf_static_broadcaster_;
};

int main(int argc, char * argv[])
{
  auto logger = rclcpp::get_logger("logger");

  if (argc != 8) {
    RCLCPP_INFO(
      logger, "Invalid number of parameters\nusage: "
      "$ ros2 run learning_tf2_cpp static_turtle_tf2_broadcaster "
      "child_frame_name x y z roll pitch yaw");
    return 1;
  }

  if (strcmp(argv[1], "world") == 0) {
    RCLCPP_INFO(logger, "Your static turtle name cannot be 'world'");
    return 1;
  }

  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<StaticFramePublisher>(argv));
  rclcpp::shutdown();
  return 0;
}
```

## Writing a (dynamic) broadcaster (Python)
**Source**: https://docs.ros.org/en/jazzy/Tutorials/Intermediate/Tf2/Writing-A-Tf2-Broadcaster-Py.html

Republishes a frame every time a sensor / source updates. This is what a
real drone broadcaster looks like — a callback turns each pose update into
a `TransformStamped` and pushes it via `TransformBroadcaster.sendTransform`.

**Full `turtle_tf2_broadcaster.py`:**

```python
import math
from geometry_msgs.msg import TransformStamped
import numpy as np
import rclpy
from rclpy.node import Node
from tf2_ros import TransformBroadcaster
from turtlesim.msg import Pose

def quaternion_from_euler(ai, aj, ak):
    ai /= 2.0
    aj /= 2.0
    ak /= 2.0
    ci = math.cos(ai)
    si = math.sin(ai)
    cj = math.cos(aj)
    sj = math.sin(aj)
    ck = math.cos(ak)
    sk = math.sin(ak)
    cc = ci*ck
    cs = ci*sk
    sc = si*ck
    ss = si*sk

    q = np.empty((4, ))
    q[0] = cj*sc - sj*cs
    q[1] = cj*ss + sj*cc
    q[2] = cj*cs - sj*sc
    q[3] = cj*cc + sj*ss
    return q

class FramePublisher(Node):
    def __init__(self):
        super().__init__('turtle_tf2_frame_publisher')
        self.turtlename = self.declare_parameter(
            'turtlename', 'turtle').get_parameter_value().string_value
        self.tf_broadcaster = TransformBroadcaster(self)
        self.subscription = self.create_subscription(
            Pose,
            f'/{self.turtlename}/pose',
            self.handle_turtle_pose,
            1)

    def handle_turtle_pose(self, msg):
        t = TransformStamped()
        t.header.stamp = self.get_clock().now().to_msg()
        t.header.frame_id = 'world'
        t.child_frame_id = self.turtlename
        t.transform.translation.x = msg.x
        t.transform.translation.y = msg.y
        t.transform.translation.z = 0.0
        q = quaternion_from_euler(0, 0, msg.theta)
        t.transform.rotation.x = q[0]
        t.transform.rotation.y = q[1]
        t.transform.rotation.z = q[2]
        t.transform.rotation.w = q[3]
        self.tf_broadcaster.sendTransform(t)

def main():
    rclpy.init()
    node = FramePublisher()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    rclpy.shutdown()
```

## Writing a (dynamic) broadcaster (C++)
**Source**: https://docs.ros.org/en/jazzy/Tutorials/Intermediate/Tf2/Writing-A-Tf2-Broadcaster-Cpp.html

Same node, C++ version (composed from the upstream tutorial structure):

```cpp
#include <functional>
#include <memory>
#include <string>

#include "geometry_msgs/msg/transform_stamped.hpp"
#include "rclcpp/rclcpp.hpp"
#include "tf2/LinearMath/Quaternion.hpp"
#include "tf2_ros/transform_broadcaster.hpp"
#include "turtlesim/msg/pose.hpp"

class FramePublisher : public rclcpp::Node
{
public:
  FramePublisher() : Node("turtle_tf2_frame_publisher")
  {
    turtlename_ = this->declare_parameter<std::string>("turtlename", "turtle");
    tf_broadcaster_ = std::make_unique<tf2_ros::TransformBroadcaster>(*this);

    std::ostringstream stream;
    stream << "/" << turtlename_.c_str() << "/pose";
    std::string topic_name = stream.str();

    subscription_ = this->create_subscription<turtlesim::msg::Pose>(
      topic_name, 10,
      std::bind(&FramePublisher::handle_turtle_pose, this, std::placeholders::_1));
  }

private:
  void handle_turtle_pose(const std::shared_ptr<turtlesim::msg::Pose> msg)
  {
    geometry_msgs::msg::TransformStamped t;

    t.header.stamp = this->get_clock()->now();
    t.header.frame_id = "world";
    t.child_frame_id = turtlename_.c_str();

    t.transform.translation.x = msg->x;
    t.transform.translation.y = msg->y;
    t.transform.translation.z = 0.0;

    tf2::Quaternion q;
    q.setRPY(0, 0, msg->theta);
    t.transform.rotation.x = q.x();
    t.transform.rotation.y = q.y();
    t.transform.rotation.z = q.z();
    t.transform.rotation.w = q.w();

    tf_broadcaster_->sendTransform(t);
  }

  rclcpp::Subscription<turtlesim::msg::Pose>::SharedPtr subscription_;
  std::unique_ptr<tf2_ros::TransformBroadcaster> tf_broadcaster_;
  std::string turtlename_;
};

int main(int argc, char * argv[])
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<FramePublisher>());
  rclcpp::shutdown();
  return 0;
}
```

## Writing a listener (Python)
**Source**: https://docs.ros.org/en/jazzy/Tutorials/Intermediate/Tf2/Writing-A-Tf2-Listener-Py.html

A listener creates a `Buffer` plus a `TransformListener`; the listener
subscribes to `/tf` and `/tf_static` in the background and fills the buffer.
You then call `buffer.lookup_transform(target, source, time)` to extract
chained transforms. Use `rclpy.time.Time()` (zero) to get the latest
available transform.

**Full `turtle_tf2_listener.py`:**

```python
import math

from geometry_msgs.msg import Twist

import rclpy
from rclpy.node import Node

from tf2_ros import TransformException
from tf2_ros.buffer import Buffer
from tf2_ros.transform_listener import TransformListener

from turtlesim.srv import Spawn

class FrameListener(Node):

    def __init__(self):
        super().__init__('turtle_tf2_frame_listener')

        self.target_frame = self.declare_parameter(
            'target_frame', 'turtle1').get_parameter_value().string_value

        self.tf_buffer = Buffer()
        self.tf_listener = TransformListener(self.tf_buffer, self)

        self.spawner = self.create_client(Spawn, 'spawn')
        self.turtle_spawning_service_ready = False
        self.turtle_spawned = False

        self.publisher = self.create_publisher(Twist, 'turtle2/cmd_vel', 1)
        self.timer = self.create_timer(1.0, self.on_timer)

    def on_timer(self):
        from_frame_rel = self.target_frame
        to_frame_rel = 'turtle2'

        if self.turtle_spawning_service_ready:
            if self.turtle_spawned:
                try:
                    t = self.tf_buffer.lookup_transform(
                        to_frame_rel,
                        from_frame_rel,
                        rclpy.time.Time())
                except TransformException as ex:
                    self.get_logger().info(
                        f'Could not transform {to_frame_rel} to {from_frame_rel}: {ex}')
                    return

                msg = Twist()
                scale_rotation_rate = 1.0
                msg.angular.z = scale_rotation_rate * math.atan2(
                    t.transform.translation.y,
                    t.transform.translation.x)

                scale_forward_speed = 0.5
                msg.linear.x = scale_forward_speed * math.sqrt(
                    t.transform.translation.x ** 2 +
                    t.transform.translation.y ** 2)

                self.publisher.publish(msg)
            else:
                if self.result.done():
                    self.get_logger().info(
                        f'Successfully spawned {self.result.result().name}')
                    self.turtle_spawned = True
                else:
                    self.get_logger().info('Spawn is not finished')
        else:
            if self.spawner.service_is_ready():
                request = Spawn.Request()
                request.name = 'turtle2'
                request.x = float(4)
                request.y = float(2)
                request.theta = float(0)
                self.result = self.spawner.call_async(request)
                self.turtle_spawning_service_ready = True
            else:
                self.get_logger().info('Service is not ready')

def main():
    rclpy.init()
    node = FrameListener()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    rclpy.shutdown()
```

## Writing a listener (C++)
**Source**: https://docs.ros.org/en/jazzy/Tutorials/Intermediate/Tf2/Writing-A-Tf2-Listener-Cpp.html

**Full `turtle_tf2_listener.cpp`:**

```cpp
#include <chrono>
#include <functional>
#include <memory>
#include <string>

#include "geometry_msgs/msg/transform_stamped.hpp"
#include "geometry_msgs/msg/twist.hpp"
#include "rclcpp/rclcpp.hpp"
#include "tf2/exceptions.hpp"
#include "tf2_ros/transform_listener.hpp"
#include "tf2_ros/buffer.hpp"
#include "turtlesim/srv/spawn.hpp"

using namespace std::chrono_literals;

class FrameListener : public rclcpp::Node
{
public:
  FrameListener()
  : Node("turtle_tf2_frame_listener"),
    turtle_spawning_service_ready_(false),
    turtle_spawned_(false)
  {
    target_frame_ = this->declare_parameter<std::string>("target_frame", "turtle1");

    tf_buffer_ = std::make_unique<tf2_ros::Buffer>(this->get_clock());
    tf_listener_ = std::make_shared<tf2_ros::TransformListener>(*tf_buffer_);

    spawner_ = this->create_client<turtlesim::srv::Spawn>("spawn");
    publisher_ = this->create_publisher<geometry_msgs::msg::Twist>("turtle2/cmd_vel", 1);

    timer_ = this->create_wall_timer(1s, [this]() { return this->on_timer(); });
  }

private:
  void on_timer()
  {
    std::string fromFrameRel = target_frame_.c_str();
    std::string toFrameRel = "turtle2";

    if (turtle_spawning_service_ready_) {
      if (turtle_spawned_) {
        geometry_msgs::msg::TransformStamped t;

        try {
          t = tf_buffer_->lookupTransform(
            toFrameRel, fromFrameRel,
            tf2::TimePointZero);
        } catch (const tf2::TransformException & ex) {
          RCLCPP_INFO(this->get_logger(),
            "Could not transform %s to %s: %s",
            toFrameRel.c_str(), fromFrameRel.c_str(), ex.what());
          return;
        }

        geometry_msgs::msg::Twist msg;
        static const double scaleRotationRate = 1.0;
        msg.angular.z = scaleRotationRate * atan2(
          t.transform.translation.y, t.transform.translation.x);

        static const double scaleForwardSpeed = 0.5;
        msg.linear.x = scaleForwardSpeed * sqrt(
          pow(t.transform.translation.x, 2) +
          pow(t.transform.translation.y, 2));

        publisher_->publish(msg);
      } else {
        RCLCPP_INFO(this->get_logger(), "Successfully spawned");
        turtle_spawned_ = true;
      }
    } else {
      if (spawner_->service_is_ready()) {
        auto request = std::make_shared<turtlesim::srv::Spawn::Request>();
        request->x = 4.0;
        request->y = 2.0;
        request->theta = 0.0;
        request->name = "turtle2";

        using ServiceResponseFuture =
          rclcpp::Client<turtlesim::srv::Spawn>::SharedFuture;
        auto response_received_callback = [this](ServiceResponseFuture future) {
          auto result = future.get();
          if (strcmp(result->name.c_str(), "turtle2") == 0) {
            turtle_spawning_service_ready_ = true;
          } else {
            RCLCPP_ERROR(this->get_logger(), "Service callback result mismatch");
          }
        };
        auto result = spawner_->async_send_request(request, response_received_callback);
      } else {
        RCLCPP_INFO(this->get_logger(), "Service is not ready");
      }
    }
  }

  bool turtle_spawning_service_ready_;
  bool turtle_spawned_;
  rclcpp::Client<turtlesim::srv::Spawn>::SharedPtr spawner_{nullptr};
  rclcpp::TimerBase::SharedPtr timer_{nullptr};
  rclcpp::Publisher<geometry_msgs::msg::Twist>::SharedPtr publisher_{nullptr};
  std::shared_ptr<tf2_ros::TransformListener> tf_listener_{nullptr};
  std::unique_ptr<tf2_ros::Buffer> tf_buffer_;
  std::string target_frame_;
};

int main(int argc, char * argv[])
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<FrameListener>());
  rclcpp::shutdown();
  return 0;
}
```

## Adding a frame (Python)
**Source**: https://docs.ros.org/en/jazzy/Tutorials/Intermediate/Tf2/Adding-A-Frame-Py.html

Adds a child frame `carrot1` under `turtle1`. Two flavors: a fixed offset
broadcaster and a time-varying one. With `target_frame=carrot1`, the chasing
turtle now follows the offset frame instead of `turtle1` directly — this is
the same pattern you'd use to track an object expressed in the camera frame
while reasoning about it in the body or world frame.

**Fixed-frame broadcaster (`fixed_frame_tf2_broadcaster.py`):**

```python
from geometry_msgs.msg import TransformStamped

        self.timer = self.create_timer(0.1, self.broadcast_timer_callback)

    def broadcast_timer_callback(self):
        t = TransformStamped()
        t.header.stamp = self.get_clock().now().to_msg()
        t.header.frame_id = 'turtle1'
        t.child_frame_id = 'carrot1'
        t.transform.translation.x = 0.0
        t.transform.translation.y = 2.0
        t.transform.translation.z = 0.0
        t.transform.rotation.x = 0.0
        t.transform.rotation.y = 0.0
        t.transform.rotation.z = 0.0
        t.transform.rotation.w = 1.0
        self.tf_broadcaster.sendTransform(t)

def main():
    rclpy.init()

        rclpy.spin(node)
```

## tf2 and time (C++)
**Source**: https://docs.ros.org/en/jazzy/Tutorials/Intermediate/Tf2/Learning-About-Tf2-And-Time-Cpp.html

Why the listener uses `tf2::TimePointZero` instead of "now":

```cpp
t = tf_buffer_->lookupTransform(toFrameRel, fromFrameRel, tf2::TimePointZero);
```

`tf2::TimePointZero` means "give me the latest available transform". If you
naively replace it with `this->get_clock()->now()`, the call typically fails
with "the frame does not exist or the data is in the future" because newly
broadcast transforms take a few milliseconds to traverse the network and
land in the listener's buffer.

**Fix: pass a timeout** so `lookupTransform` blocks (up to that duration)
waiting for the requested data:

```cpp
rclcpp::Time now = this->get_clock()->now();
try {
  t = tf_buffer_->lookupTransform(toFrameRel, fromFrameRel, now, 50ms);
} catch (const tf2::TransformException & ex) {
  // ...
}
```

The fourth argument is the timeout. The call returns as soon as the
transform is available, or throws after the timeout expires. Many tf2_ros
APIs accept either `tf2::TimePoint` or `rclcpp::Time` and convert
automatically.

## Time travel with tf2 (C++)
**Source**: https://docs.ros.org/en/jazzy/Tutorials/Intermediate/Tf2/Time-Travel-With-Tf2-Cpp.html

tf2 can do more than "what is the relationship between frames now"; it can
answer "what is the position of frame A *now* relative to where frame B was
*5 seconds ago*". This is the canonical use case for predicting where a
moving target will be after compensating for sensor latency.

**Naive (broken) — same past time on both sides:**

```cpp
rclcpp::Time when = this->get_clock()->now() - rclcpp::Duration(5, 0);
try {
  t = tf_buffer_->lookupTransform(toFrameRel, fromFrameRel, when, 50ms);
} catch (...) {}
```

This asks for both frames at the same past time and produces erratic chase
behavior.

**Correct: 6-argument advanced lookup** with an explicit fixed frame:

```cpp
rclcpp::Time now = this->get_clock()->now();
rclcpp::Time when = now - rclcpp::Duration(5, 0);
try {
  t = tf_buffer_->lookupTransform(
        toFrameRel,   // 1. target frame
        now,          // 2. target time (current)
        fromFrameRel, // 3. source frame
        when,         // 4. source time (5 s ago)
        "world",      // 5. fixed frame (used to bridge time)
        50ms);        // 6. timeout
} catch (...) {}
```

How the fixed frame works: tf2 first asks "where was `fromFrame` in `world`
at `when`", then advances through time within `world` (assumed fixed), then
asks "where is `toFrame` in `world` at `now`", and composes the two. The
`world` frame must be one that does not move during the bridging interval.

## Debugging tf2 problems
**Source**: https://docs.ros.org/en/jazzy/Tutorials/Intermediate/Tf2/Debugging-Tf2-Problems.html

Systematic 4-step workflow:

1. **Read the code** — confirm which frames you're requesting and which you're
   broadcasting.
2. **`tf2_echo`** — verify the requested transform actually exists.
3. **`view_frames`** — visualize the whole tree to spot disconnects, missing
   parents, or duplicate parents.
4. **`tf2_monitor`** — check publish rates and end-to-end delays.

### Diagnostic commands

```bash
# Are these two frames known and connected?
ros2 run tf2_ros tf2_echo <target_frame> <source_frame>
# e.g.
ros2 run tf2_ros tf2_echo turtle3 turtle1

# Render the entire tree.
ros2 run tf2_tools view_frames           # produces frames.pdf

# Per-frame rates and delays along the chain.
ros2 run tf2_ros tf2_monitor <target_frame> <source_frame>
```

`tf2_monitor` reports:

- Net delay (average, max) for the requested chain.
- Per-frame: average delay, max delay.
- Per broadcaster: name, average rate.

A typical healthy "average delay" is on the order of a few milliseconds —
that's why a request with `now()` and zero timeout will usually fail.

### Common errors and fixes

**"<frame> passed to lookupTransform argument target_frame does not exist".**
A typo or a frame nobody publishes. Run `view_frames` to confirm the spelling
and existence of the frame; check that the broadcaster is actually running.

**"Lookup would require extrapolation into the future. Requested time [X] but
the latest data is at time [Y]".** You asked for `now` but data is still in
flight. Three valid fixes (in order of preference):

1. Latest available data:
   ```cpp
   t = tf_buffer_->lookupTransform(toFrameRel, fromFrameRel, tf2::TimePointZero);
   ```
2. Add a timeout:
   ```cpp
   t = tf_buffer_->lookupTransform(
         toFrameRel, fromFrameRel,
         this->now(),
         rclcpp::Duration::from_seconds(0.05));
   ```
3. Query in the past (use the buffer history deliberately):
   ```cpp
   t = tf_buffer_->lookupTransform(
         toFrameRel, fromFrameRel,
         this->now() - rclcpp::Duration::from_seconds(0.1));
   ```

### Other failure modes worth knowing about

- **Two parents for one child**: tf2 is a tree, so each child must have exactly
  one parent. If two broadcasters both publish `world -> base_link`, behavior is
  undefined. `view_frames` will surface this.
- **Disconnected subtrees / no common ancestor**: `lookup_transform` raises
  `ConnectivityException`. Add the missing static link (e.g. `map -> odom`).
- **Time skew between machines**: clocks must be synced (chrony / NTP) for
  multi-host setups; otherwise stamps don't line up and lookups extrapolate.
- **Static transform never broadcast**: `/tf_static` is latched, so a node
  that publishes static transforms must outlive the listener at least until
  the listener has received them; or use the `static_transform_publisher`.

## Quaternion fundamentals
**Source**: https://docs.ros.org/en/jazzy/Tutorials/Intermediate/Tf2/Quaternion-Fundamentals.html

ROS uses **w-last** quaternions: `(x, y, z, w)`. This is opposite to libraries
like Eigen that use w-first; copy-pasting between the two without re-ordering
is a classic bug.

The identity (no rotation) is `(0, 0, 0, 1)` — "the commonly-used unit
quaternion that yields no rotation about the x/y/z axes is (0, 0, 0, 1)."

Quaternions must be unit length. If numerical drift produces magnitude not
equal to 1, ROS prints warnings — call `normalize()` after composing.

### RPY to quaternion

**C++:**

```cpp
#include <tf2/LinearMath/Quaternion.h>

tf2::Quaternion q;
q.setRPY(0, 0, 0);  // roll, pitch, yaw in radians
RCLCPP_INFO(this->get_logger(), "%f %f %f %f", q.x(), q.y(), q.z(), q.w());
q.normalize();
```

**Python (using the same `quaternion_from_euler` pattern as in the
broadcaster tutorials, or `tf_transformations.quaternion_from_euler`):**

```python
q = quaternion_from_euler(1.5707, 0, -1.5707)
print(f'The quaternion representation is x: {q[0]} y: {q[1]} z: {q[2]} w: {q[3]}.')
```

### Composing rotations (multiplication)

Order matters: `q_new = q_rot * q_orig` applies `q_orig` first, then `q_rot`.

**C++:**

```cpp
tf2::Quaternion q_orig, q_rot, q_new;
q_orig.setRPY(0.0, 0.0, 0.0);
q_rot.setRPY(3.14159, 0.0, 0.0); // 180 deg about X
q_new = q_rot * q_orig;
q_new.normalize();
```

**Python:**

```python
q_orig = quaternion_from_euler(0, 0, 0)
q_rot  = quaternion_from_euler(3.14159, 0, 0)
q_new  = quaternion_multiply(q_rot, q_orig)
```

### Inverse (conjugate of a unit quaternion)

Negate x, y, z; keep w:

```python
q_inv = [-q[0], -q[1], -q[2], q[3]]
```

### Relative rotation

If `q_2 = q_r * q_1`, then `q_r = q_2 * inverse(q_1)`. This is how you go
from "I have two absolute orientations" to "what rotation maps one to the
other".

### Quaternion <-> message

```cpp
#include <tf2_geometry_msgs/tf2_geometry_msgs.hpp>

geometry_msgs::msg::Quaternion msg_quat = tf2::toMsg(tf2_quat);
tf2::Quaternion tf2_quat_from_msg;
tf2::fromMsg(msg_quat, tf2_quat_from_msg);
```

`geometry_msgs/msg/Quaternion` has fields `x, y, z, w` (w-last).

In Python the wire format is the same; libraries typically use a 4-element
list/tuple `[x, y, z, w]`.

### Reading RPY back from a quaternion (C++)

```cpp
#include <tf2/LinearMath/Matrix3x3.h>
double roll, pitch, yaw;
tf2::Matrix3x3(q).getRPY(roll, pitch, yaw);
```

## Stamped data with `tf2_ros::MessageFilter`
**Source**: https://docs.ros.org/en/jazzy/Tutorials/Intermediate/Tf2/Using-Stamped-Datatypes-With-Tf2-Ros-MessageFilter.html

Pattern: a sensor publishes stamped data (`PointStamped`, `PoseStamped`,
`PointCloud2`, etc.) in some frame, and you want to consume it in a different
frame. Naively calling `buffer.transform()` inside the topic callback often
fails because the necessary transforms haven't arrived yet. `MessageFilter`
solves this: it queues incoming messages and only invokes your callback once
the required transform into the target frame is available (or a timeout
expires).

### Broadcaster (Python) — publishes `turtle3` pose as `PointStamped` in `world`

```python
ps = PointStamped()
ps.header.stamp = self.get_clock().now().to_msg()
ps.header.frame_id = 'world'
ps.point.x = msg.x
ps.point.y = msg.y
ps.point.z = 0.0
self.pub.publish(ps)
```

Topic: `/turtle3/turtle_point_stamped`.

### Listener (C++) — `MessageFilter` setup

```cpp
point_sub_.subscribe(this, "/turtle3/turtle_point_stamped");

tf2_filter_ = std::make_shared<tf2_ros::MessageFilter<
    geometry_msgs::msg::PointStamped>>(
  point_sub_,
  *tf2_buffer_,
  target_frame_,            // e.g. "turtle1"
  100,                      // queue size
  this->get_node_logging_interface(),
  this->get_node_clock_interface(),
  buffer_timeout);

tf2_filter_->registerCallback(&PoseDrawer::msgCallback, this);
```

Constructor args, in order:

1. `point_sub_` — a `message_filters::Subscriber` for the input topic.
2. `*tf2_buffer_` — the `tf2_ros::Buffer` to consult.
3. `target_frame_` — frame the consumer wants the data in.
4. `100` — internal queue size (drop oldest after this many).
5. logging interface, clock interface — standard rclcpp wiring.
6. `buffer_timeout` — how long to wait for the transform per message.

### Callback — actually transform the message

```cpp
void msgCallback(const geometry_msgs::msg::PointStamped::SharedPtr point_ptr)
{
  geometry_msgs::msg::PointStamped point_out;
  try {
    tf2_buffer_->transform(*point_ptr, point_out, target_frame_);
    RCLCPP_INFO(this->get_logger(),
      "Point of turtle3 in frame of turtle1: x:%f y:%f z:%f\n",
      point_out.point.x, point_out.point.y, point_out.point.z);
  } catch (const tf2::TransformException & ex) {
    RCLCPP_WARN(this->get_logger(), "Failure %s\n", ex.what());
  }
}
```

The filter has already verified `canTransform(target_frame_, msg.header.frame_id,
msg.header.stamp)`, so the `transform()` call should succeed; the catch is
defensive.

`lidar`, etc.) that you need to fuse in `base_link` or `map`, wrap the
subscription in a `MessageFilter` and let tf2 do the synchronization.
